# Command-line interfaces

`reasoning-dev` provides source-tree `serve`, `check`, `dependencies`, and
`time` commands. Use `make dev` and `make check-fast` for the supported local
development loop; fixture credentials, state boundaries, check selection, and
CI are described in [Development](development.md). It does not manage a cloud
deployment or submit paid inference.

The Python distribution installs ten commands. Run command-driven interfaces
and their subcommands with `--help` before using an advanced path; the help
generated by the installed revision is authoritative for flags.

| Command | Purpose | Primary guide |
| --- | --- | --- |
| `reasoning-deploy` | Build, inspect, deploy, upgrade, recover, and manage separate compute hosts | [Deployment](deployment.md), [operations](operations.md) |
| `reasoning-dev` | Start local fixtures, run scoped checks, cache dependencies, and time phases | [Development](development.md) |
| `reasoning-server` | Initialize, administer, back up, recover, and serve one organization installation | [Server](server.md), [backup](backup.md) |
| `reasoning-compute-worker` | Configure and run a separate Docker or Modal execution worker | [Compute](compute.md) |
| `reasoning-work-worker` | Run explicitly enrolled internal job assignments | [Internal execution](work-execution.md) |
| `reasoning-bot` | Pair/run Codex or Claude Code, configure scoped clients, and post notifications | [Bots](bots.md) |
| `reasoning-bot-cloud` | Quote, provision, install and sign in to a dedicated DigitalOcean CLI bot | [Cloud bots](bots.md#codex-and-claude-code-dedicated-digitalocean-bot) |
| `reasoning-bot-webhook` | Serve or recover the journaled arithmetic webhook example | [Bots](bots.md#outgoing-webhooks) |
| `make bot-connect` | Prompt for the server, browser-pair a personal CLI bot, and start its runner | [Bots](bots.md#codex-and-claude-code-connect-from-your-computer) |
| `make bot-cloud` | Guided dedicated DigitalOcean bot with optional CAS/Lean and private retry state | [Cloud bots](bots.md#codex-and-claude-code-dedicated-digitalocean-bot) |
| `make bot-cloud-enable` | Explicit operator opt-in for owned server outbound SSH, preserving inbound restrictions | [Cloud bots](bots.md#codex-and-claude-code-dedicated-digitalocean-bot) |
| `make compute-setup` | Enable Modal relays for an existing synchronized organization | [Compute](compute.md#enable-compute-on-an-existing-deployment) |
| `make email-setup` | Enable private Resend invitations and verification on an existing managed server | [Deployment](deployment.md#configure-invitation-email-separately-on-an-installed-host) |
| `make compute-images` | Queue real CPU image acceptance; `COMPUTE_RETAIN_CANDIDATE=true` retains private review archives | [Images](images.md#build-local-candidates) |
| `make compute-source-publish` | Maintainer-only Spaces source upload, with hidden credentials and paid/publication confirmation | [Source publication](image-review.md#public-source-delivery-with-digitalocean-spaces) |
| `reasoning-ledger` | Connect/import a canonical organization ledger or maintain a standalone claim/proof ledger | [Organization ledger](organization-ledger.md), [web workbench](../web/README.md) |
| `reasoning-ledger-web` | Run the local research workbench | [Web workbench](../web/README.md) |

`reasoning-ledger-web` is the exception: it starts the loopback server directly.

Beta-topic agents run automatically with `reasoning-server serve`; they do not
require `reasoning-work-worker`. `serve --agent-concurrency N` selects 1–256
simultaneous native assignments, default 8. See [topic agents](topic-agents.md)
for delegation, steering, bot permissions, and recovery limits.
Its port and other startup settings are environment variables documented in the
[web guide](../web/README.md#run).

## Supported convenience commands

The repository Makefile exposes the common source-checkout paths:

```text
make build
make deploy
make upgrade
make upgrade-resume
make onboard
make onboard ONBOARD_REPLACE_TOKEN=1
make doctor
make operator-sync
make inspect
make operator-authorize
make operator-join OPERATOR_HANDOFF=/path/to/handoff.tar.gz OPERATOR_IDENTITY=/path/to/key DO_TOKEN_FILE=/path/to/token OPERATOR_HANDOFF_SHA256=…
make operator-kit RECOVERY_KIT=/secure/recovery.rnrk
make operator-recover RECOVERY_KIT=/secure/recovery.rnrk DO_TOKEN_FILE=/secure/token
```

Run `make help` for current overrides. `make deploy`, `make upgrade`, and
`make onboard` are interactive operations with private retry state. Onboarding
prepares a separate key, guides authenticated operator handoff, privately
collects the own Team token, and joins/verifies without upgrading. It can pause
before receiving the handoff. Keep both `ONBOARD_STATE` and `DEPLOY_STATE`
afterward; see [operator onboarding](operations.md#add-a-deployment-operator).
Use `ONBOARD_REPLACE_TOKEN=1` (direct CLI: `reasoning-deploy onboard --replace-token`)
to privately collect a new same-Team token and update a completed join without
repeating it, or to retry a join that wrote no deployment state. Keep the old
token files until verification, then revoke the old token at the provider.
Operator tokens require `account:read`, `domain:read`, `droplet:read`,
`tag:read`, `firewall:read`, and `firewall:update`.
Keep original state directories and release inputs until a verified terminal
phase; partial/inconsistent joins stop for reconciliation instead of replay.
`make operator-authorize` asks for the collaborator's public-key file unless
`OPERATOR_PUBLIC_KEY` is set, and writes the handoff to
`DEPLOY_STATE/handoffs/` unless `OPERATOR_HANDOFF` is set. `make onboard` and
`make doctor` end with the verified checks; the last line of standard output
is the JSON receipt.

`reasoning-ledger --root /path/to/ledger organization-link --config /secure/bot.json`
connects a workbench to the organization's canonical research ledger.
`organization-import` explicitly publishes source records with provenance and a
retained private retry journal; `organization-status` inspects the connection.
Follow the [organization-ledger guide](organization-ledger.md) for scoped grants,
exact import commands, and human-reviewed claim states.

Advanced `reasoning-deploy` subcommands are intentionally documented in the
workflow that owns them rather than as isolated copy-and-paste fragments. This
keeps confirmation strings, retained inputs, and recovery rules adjacent to the
operation they authorize.
